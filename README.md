## 01. PLA Edge Lifting Troubleshooting Guide

**Type:** Self-directed technical writing sample  
**Audience:** Beginner-to-intermediate desktop FDM printer users  
**Output:** PDF guide, HTML output, DITA source files

This project is a DITA-based troubleshooting guide for users who experience edge lifting or minor warping when printing PLA on entry-level FDM printers.

The guide helps users decide whether the troubleshooting path applies to their situation, choose the right check based on symptoms, and test one factor at a time. It includes a scope decision table, quick checklist, symptom-to-check guide, step-by-step troubleshooting sections, escalation table, concept explanation, and key terms.

**What I practiced in this project:**

- defining the scope and limits of a troubleshooting guide
- organizing symptoms, causes, recommended actions, and result checks
- writing direct and cautious user instructions
- using DITA topics and a ditamap to structure the document
- generating PDF and HTML outputs with Oxygen XML Author
- preparing visual aids for instructional clarity

## 02. Markdown Pre-translation Processing Guide

**Type:** Self-directed process guide informed by localization workflow practice  
**Audience:** Localization coordinators, junior localization specialists, technical editors, or reviewers working with Markdown source files  
**Output:** PDF guide

This process guide, written in Chinese, explains basic pre-translation processing for Markdown technical documentation before import into a CAT tool. It uses generalized examples only and does not include client or confidential project content.

The guide focuses on identifying high-risk content such as Markdown syntax, placeholders, variables, links, file paths, commands, code blocks, and source formatting issues. It also explains how to use regular expressions (Regex) as an aid for locating risks, while keeping human review and reversibility as part of the workflow.

**What I practiced in this project:**

- writing a structured internal process guide
- identifying structure-sensitive content in Markdown files
- using Regex for controlled search and risk identification
- distinguishing between content to preserve, content to clean up, and content requiring human confirmation
- designing a reviewable and reversible handoff process
- writing checklists for pre-delivery review

**File:**

- [View PDF](02_Markdown_Pretranslation_Processing/Markdown_Pretranslation_Processing_Guide.pdf)

This sample connects my localization background with technical documentation work by focusing on source-file safety, content structure, and documentation QA.

## 03. Bear Hand Mixer User Manual Localization Case Study

**Type:** Coursework-based localization and technical communication refactoring case study  
**Source / target:** Chinese source manual excerpt localized into English  
**Output:** PDF case study

This sample is based on MA coursework and is included as a localization and technical communication refactoring case study.

The project analyzes how a Chinese appliance user manual excerpt can be revised into clearer English user instructions. The focus is on revision rationale rather than presenting a full commercial documentation deliverable.

The case study covers:

- task-oriented rewriting
- reducing unnecessary politeness markers and noun-heavy phrasing
- improving list formatting and information structure
- simplifying terminology
- clarifying safety-related instructions
- explaining before/after revision decisions
